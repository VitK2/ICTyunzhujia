# 需求驱动的家具推荐与布局

日期：2026-11-14。

2026-11-16状态更新：用户已通过界面完成DeepSeek配置并测试通过，真实推荐、阅读布局修改和茶几应用链路均通过。下文“暂不填写密钥”和demo结果为11月14日阶段记录，最新结果见[DeepSeek真实联调记录](DeepSeek真实联调记录.md)。

## 体验流程

1. 打开原5174地址，在方案助手中展开「我的选购与布置需求」。
2. 填写预算8000、城市区域杭州滨江、家具偏好现代/木质、生活需求两人居住并常阅读，选择阅读布局和仅真实商品，保存需求。
3. 发送「按我的需求推荐沙发和茶几」。系统展示目录内候选、历史价格、尺寸筛选依据和未核验条件，保留现有家具摆放。
4. 在茶几卡片选择「替换同类家具」。系统以当前方案重新计算预算，保留锁定家具，替换后搜索布局，最终校验通过才更新场景。点击撤销可以回到原方案。
5. 继续发送「保留沙发，按需求修改布局」，演示模式使用已保存的阅读/会客/活动空间重点；完整自由表达留待真实模型联调。

住房位置仅记录到城市或区域。当前没有地图、配送、运费、门店库存或地区气候接口，不宣称因输入城市便完成当地可购性判断。现有30件开放素材和5条真实商品信息仍是初步数据；其中4件真实商品可落地摆放，目录覆盖很有限。家具材质/风格以名称关键词辅助检索，没有明确证据的属性保留待确认。

## 数据和执行边界

需求档案作为可选brief随Plan保存、恢复、比较和导入导出。旧版无brief的JSON仍可使用；城市最长80字，偏好和生活需求各500字。前后端共享校验。

新增update_brief、recommend_furniture工具，保留既有锁定、检索、替换、增删、布局和校验工具。推荐候选只包含后端真实目录ID，默认仅真实商品；用户可明确选择也参考开放素材。未知价格为null并提示预算缺口。推荐用已知金额计算预算余量，替换时可扣除被替换家具的旧金额；历史价不是实时成交价。

推荐动作与应用动作分开。应用接口/api/agent/apply不调用模型，使用当前方案执行用户明确选择，并重新检查商品范围、锁定状态、预算、几何条件。最终不可行或超预算不会应用；不会用删除其他家具来凑结果。客户端仍检查处理期间场景是否被手动改变，避免旧结果覆盖新场景。

生活需求文字在demo模式中主要作为已保存条件及对话上下文，固定规则仅识别有限指令；不能将demo描述成已具备大模型自由推理能力。

## DeepSeek接入准备

用户本轮决定暂不填写密钥。已准备非秘密配置：

```dotenv
AGENT_MODE=demo
AGENT_PROVIDER=DeepSeek
AGENT_API_URL=https://api.deepseek.com/chat/completions
AGENT_MODEL=deepseek-flash
AGENT_API_KEY=
```

后续仅在本地.env.local填写密钥并改为cloud，不在聊天、前端或日志里粘贴密钥。配置每次请求读取，无需重新构建。模型名称依据本次查阅的官方文档，若控制台后续变化应重新核对。

DeepSeek主机的请求显式使用thinking.type=disabled，以非思考模式演示工具调用；若服务仍返回reasoning_content，只在后端本轮会话中保留并回传，不包含在前端回复、工具轨迹或日志中。缺少密钥、鉴权失败、额度不足、接口错误会明确报错，不自动伪装成云端成功。

云端模式会将需求档案、近期文字对话和场景/家具数据发送给所配置的模型提供商。目前没有真实DeepSeek请求成功的记录；测试中的DeepSeek响应为替身。比赛所需CodeArts使用证据和华为云部署不能由本流程替代。

官方依据：[DeepSeek首次调用](https://api-docs.deepseek.com/)、[工具调用](https://api-docs.deepseek.com/guides/tool_calls/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。
